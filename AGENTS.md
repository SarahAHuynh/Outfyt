# Outfyt session instructions

Read `codex.md` at the repository root before planning or changing this application. It contains the user's product vision, accepted UI decisions, milestone workflow, setup preferences, implementation status, and next steps. Follow it alongside the user's current instructions.

Keep `codex.md` current in the same working change whenever application behavior, architecture, dependencies, configuration, migrations, setup requirements, tests, milestone status, or user decisions change. Update it before ending the session. For documentation-only work, update it when the handoff or workflow changes. Never write credentials or private user data there.

At each completed milestone or implementation phase:

1. Summarize the completed work, actual verification results, remaining setup, and next step.
2. Give the user concrete manual test cases with expected results.
3. Supply a short suggested commit message. Do not commit or push unless requested.
4. Stop for user review before starting the next milestone.

External setup instructions must be thorough and sequential: exact website/dashboard, menu/button, configuration, file path, command, expected result, and recovery steps. Guide one major setup process at a time. Never ask for secrets in chat. Do not claim hosted setup or manual acceptance passed without evidence.

If code and documentation disagree, inspect the implementation, preserve existing user work, and correct the handoff. Distinguish implemented, locally verified, deployed/configured, and user-approved status. Current user instructions take precedence over older handoff notes.
